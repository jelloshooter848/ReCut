## Report

### Summary

A roadmap proposal drafted by ChatGPT ("ReCut — Revised Roadmap and Audio Stem Separation Proposal") was reviewed
against `docs/ROADMAP.md`, `docs/LIMITATIONS.md` and the code, followed by one round of rebuttal from ChatGPT. Most of
the proposal repeats items already on the roadmap. The revisions below are the ones that survived review: one new
capability, three re-rankings, three missing entries, one documentation gap, and three design constraints for any
future implementation.

### Steps to reproduce

1. Read `docs/ROADMAP.md` and `docs/LIMITATIONS.md` on commit a72554f.
2. Compare with the requested revisions below.

### Expected

The roadmap ranks work by how much it serves restructuring finished films and series at franchise scale, and it lists
every capability the limitations page says is missing.

### Actual

#### Revisions requested

1. **Add local dialogue / music / effects stem separation (new entry).**
   Fan editors work from a finished mix. Separated stems let an editor cut dialogue while the score and ambience carry
   across the cut. Nothing like this is on the roadmap today. The existing model already supports it: `linkId`
   (`shared/model.ts:183`) groups any number of clips, so a picture clip plus four stems needs no model change. Stems
   would be generated by a job and cached like proxies.
   **Placement:** after the audio mixer work (roadmap §3) and volume keyframes (§5), not ahead of them. Stems are far
   more useful once there are meters, routing and automation. The proposal's own rebuttal makes this argument.

2. **Elevate nested sequences / compound clips out of "Smaller items".**
   They currently sit beside a titles generator (`docs/ROADMAP.md:88`). For trilogy merges and franchise cuts they are
   basic organisation, not polish. They are also expensive: they touch the preview player, the export graph,
   linked-clip sync and future interchange. Give them their own numbered entry with a plan.

3. **Give bitmap subtitle OCR its own entry next to Whisper.**
   It is currently a "Smaller items" bullet (`docs/ROADMAP.md:85`). Both OCR and Whisper produce the same thing, a
   searchable transcript track. Most Blu-ray / DVD rips carry PGS or VobSub subtitles. On those sources OCR is cheaper
   than speech recognition and keeps the authored timing, so it could reasonably ship before Whisper.

4. **Add a performance gate before the next large feature.**
   The 2,500-clip performance report "has not been re-measured since those changes" (`docs/LIMITATIONS.md:118`). The
   Playwright attack suites (`docs/LIMITATIONS.md:130`) and the acceptance gauntlet have not been re-run either. Re-run
   all three first. If the target scale (thousands of timeline clips, thousands of scenes, multi-hour sequences)
   degrades, make performance a named roadmap milestone rather than only a QA task.

5. **Add Collect / Consolidate Project (missing entry).**
   Copy a project and its media into one portable folder. This pairs with relative media roots, which today appear
   only under collaboration (§9).

6. **Add intermediate and audio-only export (missing entry).**
   ProRes, DNxHR, PCM/WAV, audio-only and stem export. `docs/LIMITATIONS.md:75` lists these as absent, but the roadmap
   has no entry for them. They matter for round-tripping to Resolve or Premiere, which is the point of interchange
   (§4).

7. **Add centre-channel extraction as a quick utility.**
   A cheap 5.1 tool (extract C, choose a source channel, controlled stereo downmix). It is useful on its own and is
   not a substitute for stem separation. It fits under surround mixing (§3).

8. **Document that moving media regenerates derived media (`docs/LIMITATIONS.md`).**
   Cache keys hash the absolute path plus size and modified time (`electron/media/cache.ts:44`). After moving media to
   a new drive and relinking, proxies, waveforms and thumbnails are probably rebuilt even for unchanged files. Not yet
   verified by test; see Scope. Portability work (item 5, §9) should address it.

#### Constraints for the stem-separation design

- **No bundled Python by default.** The Whisper plan (roadmap §1) uses a user-installed binary so ReCut stays offline
  and avoids heavy runtimes. A bundled Python + PyTorch worker would be the largest packaging cost in the app. Keep
  the engine behind an interface and run it as an isolated main-process job; prefer a user-installed or standalone
  engine.
- **Do not hash whole source files.** The proposal keys its cache on a source hash. Hashing a 40 GB remux is slow.
  Reuse the existing path + size + mtime key, plus model, model version and settings.
- **Check both licences before shipping a model:** the code licence and the pretrained-weights licence, which can
  differ. Weights trained on a dataset may inherit the dataset's terms.

#### Ordering

Separation should not outrank roadmap §2 (preview gaps). The preview currently plays the wrong audio stream for a clip
whose stream differs from the media default (`docs/LIMITATIONS.md:36`). That is a correctness gap and should come
before a large new feature.

#### Items reviewed and not requested

Already on the roadmap and ranked sensibly, so no change: Whisper (§1), surround mixer (§3), interchange
EDL / FCPXML / OTIO (§4), keyframes (§5), colour tools (§6), GPU decode (§7), multi-language subtitles (§8),
collaboration (§9). "Smart relink" already partly exists: the Relink dialog scans a folder and matches by file name
and size (`src/panels/project/RelinkDialog.tsx:27`).

### Suspected cause (hypothesis)

The roadmap was written while the timeline model and export were still settling, so it ranks by implementation risk
more than by fan-edit value. Stem separation postdates it.

  proxy, waveform and thumbnail jobs run again. If they do, file a separate report for it.
- Item 4 may produce real code bugs. File each failure from those suites as its own report.

### Root cause

The roadmap was written before the fix waves of 4–5 October and ranked by implementation risk. It had no entries
for stem separation, intermediate / audio-only export, Collect Project or centre-channel extraction, kept nested
sequences and OCR in "Smaller items", and had no performance gate. Two of its items were partly done already:
still images in the Program monitor, and Windows nsis + portable builds with bundled FFmpeg (built, installed and
smoke-tested in CI per `docs/INSTALL.md:3-20` and `.github/workflows/windows.yml`, unsigned). `docs/LIMITATIONS.md`
said the perf report, gauntlet and attack Playwright suites had not been re-run, and did not mention that moving media
rebuilds derived media.

### Fix

`docs/ROADMAP.md`, same style (Why / Why deferred / Plan, rough priority, no marketing language), renumbered 1–16:

1. Performance at franchise scale (new; a gate).
2. Preview gaps (was §2; names the stills that remain; a correctness gate before large features).
3. Bitmap subtitle OCR (new entry, out of Smaller items, next to Whisper; can ship first).
4. Whisper (was §1).
5. Nested sequences and compound clips (new numbered entry with a plan).
6. Surround mixing (was §3), with centre-channel extraction as a quick utility.
7. Interchange (was §4).
8. Intermediate and audio-only export (new: ProRes, DNxHR, PCM, WAV, per-track / per-stem).
9. Keyframes (was §5).
10. Stem separation (new; after the mixer, keyframes and preview gaps; with the three design constraints).
11. Colour (was §6). 12. GPU decode (was §7). 13. Multi-language subtitles (was §8).
14. Collect / Consolidate Project (new; pairs with relative media roots; notes the cache-key problem).
15. Collaboration (was §9).
16. Smaller items: OCR and nested sequences moved out; the "signed and tested AppImage / dmg / nsis" bullet now says
    signing / notarisation and dmg / AppImage remain, and that the Windows builds are done but unsigned.

Performance becomes a named milestone because the report's own criterion is met: at the target scale, edits take
80–122 ms commit → paint against a 32 ms budget, scrubbing at working zoom runs at 32–35 fps against 50, and opening
the project freezes the window for 3 s. Playback, search and autosave now pass, so the entry is scoped to what still
fails. It also adds a multi-hour sequence to the benchmark, because the measured sequence is only 26 min.

Existing items keep their relative order, as the report asked. Whisper moves from §1 to §4 only because the two gates
and OCR now precede it. No document links into ROADMAP section anchors (`grep -rni roadmap`: only `README.md:120`
and `docs/LIMITATIONS.md:4`, both to the file), so renumbering breaks nothing. The new link from ROADMAP §14 to
`LIMITATIONS.md#projects` resolves.

`docs/LIMITATIONS.md`: new Projects bullet "Moving media rebuilds its derived media" (item 8, with the proxy
correction); "Scale and performance" gives the 5 October re-measurement; "Reports in docs/ that are out of date"
gives today's gauntlet, e2e and attack suite results.
