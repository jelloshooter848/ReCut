## Report

### Summary

`docs/RELEASING.md` defines 1.0.0 as "the owner's call, when ReCut is stable enough for other people to rely on".
`docs/ROADMAP.md` has 19 entries and no line between 1.0 and later. Finishing every entry is the wrong bar.

- The roadmap holds **more features than a 1.0 needs.**
- It **leaves out release-quality work** that a 1.0 cannot ship without.

### Steps to reproduce

1. Read `docs/ROADMAP.md` (§1–§19, Ordering decisions) and `docs/RELEASING.md:5-11`.
2. Compare with the proposal below.

### Expected

The roadmap marks which entries are 1.0 scope and which come later. It also lists the non-feature work that 1.0
requires.

### Actual

#### What the roadmap gets right (keep)

- **Gates come first.** Performance (§1, done in 0.3.0) and preview correctness (§2) are gates.
- **Delivery comes before new systems.** §6 and §7 come before §8, §10 and §12.
- **Ordering decisions are recorded.** Each entry gives why, why deferred, and a plan.
- **It stays in ReCut's niche.** It favours restructuring finished films over copying Resolve or Premiere.

#### Entries that can wait until after 1.0

| Entry | Why it can wait |
|---|---|
| §12 Stem separation | Largest new dependency in the app; most useful after the mixer and keyframes. |
| §13 Colour tools | Needs a WebGL compositor; most fan editors grade in Resolve. |
| §14 GPU decode and preview | Proxies already cover undecodable sources. |
| §15 Multi-language subtitle authoring | Serves fan-sub work, not most recuts. |
| §17 Cloud-free collaboration | Depends on portability work that comes first. |
| §9 Full surround mixer | The centre-channel utility can ship separately. |
| §10 Interchange | Few fan editors round-trip; it must also represent nesting. |
| §19 Official Linux and macOS releases | (Update 7 October 2026) No longer parked: the owner scheduled Linux for 0.6.1 and macOS for 0.7.0, so it is no longer a candidate to leave out of 1.0 by default. |

#### Release-quality work missing from the roadmap

1. **A project-file compatibility promise.** `formatVersion` is 1, and newer files are refused.
   `docs/project-format.md:177` says future versions "bump `formatVersion` and migrate in `normalizeProject()`", but
   no migration code or tests exist. A 1.0 should promise that 1.0 projects open in every 1.x release, and test it
   with saved files from each released version.
2. **Licensing.** There is no `LICENSE` file, and the bundled GPL FFmpeg ships without its licence or source
   information. Filed separately: `bugs/closed/2026-10-07-bundled-ffmpeg-licence-not-shipped.md`.
3. **Windows code signing.** It is in §18 "Smaller items" today. A release for other people should not warn
   "unknown publisher" on every install.
4. **An update notice.** There is no updater and no update check. A "new version available" notice that checks the
   latest GitHub release, with an opt-out, is enough.
5. **A reproducible performance gate.** See `bugs/closed/2026-10-07-perf-gate-verdict-not-reproducible.md`.
6. **A stated platform scope.** Windows has tested installers. The macOS dmg is parked, and the Linux AppImage is
   untested. Say which platforms 1.0 supports.

#### Proposed 1.0 scope

| Roadmap entry | Why it belongs in 1.0 |
|---|---|
| §2 Preview gaps | The preview must play the audio stream the export renders. |
| §3 Pre-export warnings | Catches mistakes before a long export. |
| §4 Bitmap subtitle OCR | Transcript search on most Blu-ray and DVD rips. |
| §6 Intermediate and audio-only export | Hand-off to finishing tools. |
| §7 MKV packaging export | Deliver a finished fan edit without a second tool. |
| §16 Collect / Consolidate Project | Portability, with `bugs/open/2026-10-05-moved-media-cache-miss.md`. |
| §8 Nested sequences (probably) | Core organisation for franchise edits. |
| §11 Keyframes, first version (probably) | Ducking and Ken Burns moves. |

Plus the six release-quality items above.

After 1.0, proposed:

| Release | Candidates |
|---|---|
| 1.1 | §5 Whisper (OCR covers most disc sources first), §9 centre-channel utility and mixer |
| 1.x | §10, §13, §14, §15, macOS build |
| 2.0 | §12 stem separation, §17 collaboration |

### Evidence

- `docs/RELEASING.md:5-11`, `docs/ROADMAP.md` §1–§19, `docs/project-format.md:29,177`, `package.json:8`,

### Suspected cause (hypothesis)

The roadmap is ordered by fan-edit value, and 1.0 was left as an open owner decision, so nothing marks a cut line.

### Scope

- If adopted: add a "1.0 scope" section (or a 1.0 tag on each entry) to `docs/ROADMAP.md`, and move code signing out
  of §18. `docs/RELEASING.md` could link to it from the 1.0.0 row.
- The licensing gap affects published releases now. It is filed separately so it can be fixed without waiting for
  this decision.

### Root cause

1.0 was left as an open owner decision, so the roadmap had no cut line.

### Fix

The owner decided the scope on 7 October 2026:
- **In 1.0:** official Linux (0.6.1) and macOS (0.7.0) releases; delivery in two releases (0.8.0 intermediates and
  audio, with the centre-channel utility; 0.9.0 MKV packaging); portability and trust (0.10.0: Collect, the
  moved-media cache fix, a project compatibility promise tested with saved-project fixtures, an update notice);
  local transcription (0.11.0, engine built in, models downloaded); nested sequences (0.12.0); keyframes v1
  (0.13.0, first to move to 1.1 if 1.0 needs cutting).
- **Release candidates and an exit checklist,** including the owner's real-media test pass and a week of normal use.
- **Windows code signing is not required for 1.0** (no paid certificate for a free project; after 1.0, a free
  open-source signing programme or a sponsor). macOS is signed from 0.7.0.

Changes from this report's proposal: Whisper moved from 1.1 into 1.0 (with the engine bundled, its main cost, the
installer size, goes away); macOS moved from 1.x into 1.0 (owner's decision on §19); Windows code signing moved out
of the 1.0 requirements. The licensing, perf-gate and platform-scope items were fixed separately (0.4.1, 0.5.0, §19).

### Before / after

Before: `docs/RELEASING.md` said 1.0.0 is "the owner's call"; the roadmap had no 1.0 line. After: ROADMAP → Road to
1.0 lists the milestones, what is required, what is cut first, the release-candidate work and the ready-for-1.0
checklist.
